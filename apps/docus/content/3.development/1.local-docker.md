The project includes Docker Compose configurations for development and production environments.

## Prerequisites

Before using Docker development, ensure **Supabase is running locally**:

```bash [Terminal]
# Start Supabase (PostgreSQL, Auth, Storage)
supabase start

# Verify it's running
supabase status
```

The Docker dev environment connects to Supabase via `host.docker.internal`.

## Development Setup

The `docker-compose.dev.yml` file provides:

- Express API with hot reload (tsx watch)
- Nuxt frontend with HMR (Hot Module Replacement)
- Volume mounts for live code updates
- Connection to Supabase on host machine

### Starting the Environment

```bash [Terminal]
# Start all services
pnpm docker:dev

# Or start in detached mode
pnpm docker:dev:detach

# View logs
pnpm docker:logs
```

### What's Running

| Container | Port | Description |
|-----------|------|-------------|
| `turbo-api-dev` | 3002 | Express API with tsx watch |
| `turbo-nuxt-dev` | 3001 | Nuxt with HMR |

Plus Supabase services on the host:

| Service | Port | Description |
|---------|------|-------------|
| Supabase API | 54321 | REST API |
| PostgreSQL | 54322 | Database |
| Supabase Studio | 54323 | Web UI |

## Docker Compose Files

### docker-compose.dev.yml

Development environment connecting to Supabase:

```yaml
services:
  api:
    build:
      dockerfile: apps/api/Dockerfile.dev
      target: dev
    environment:
      - DATABASE_URL=postgresql://postgres:postgres@host.docker.internal:54322/postgres
      - SUPABASE_URL=http://host.docker.internal:54321
    volumes:
      - ./apps/api/src:/app/apps/api/src:ro

  nuxt:
    build:
      dockerfile: apps/nuxt/Dockerfile.dev
      target: dev
    depends_on:
      - api
```

### docker-compose.db.yml

Standalone PostgreSQL (alternative to Supabase):

```bash [Terminal]
# Start just the database
pnpm docker:db

# Connect from host machine
psql postgresql://postgres:postgres@localhost:54322/postgres
```

Use this if you don't want to run full Supabase locally.

### docker-compose.yml

Production configuration with multi-stage builds:

```bash [Terminal]
# Build and run production containers
pnpm docker:prod
```

## Development Dockerfiles

Each app has a `Dockerfile.dev` optimized for development:

### apps/api/Dockerfile.dev

```dockerfile
FROM node:22-alpine AS base
# ... base setup

FROM base AS pruner
COPY . .
RUN pnpx turbo prune api --docker

FROM base AS dev
COPY --from=pruner /app/out/json/ .
RUN pnpm install --frozen-lockfile
COPY --from=pruner /app/out/full/ .

CMD ["pnpm", "--filter=api", "dev"]
```

Key features:
- Uses `turbo prune` for minimal image size
- Runs `tsx watch` for hot reload
- Volume mounts override source files

### apps/nuxt/Dockerfile.dev

Similar pattern with Nuxt-specific HMR configuration.

## Environment Variables

Development containers use these defaults:

```env
# Database (connects to Supabase on host)
DATABASE_URL=postgresql://postgres:postgres@host.docker.internal:54322/postgres

# Supabase
SUPABASE_URL=http://host.docker.internal:54321

# API CORS
CORS_ORIGIN=http://localhost:3001,http://localhost:3000

# Logging
LOG_LEVEL=debug
```

## Docker Commands Reference

```bash [Terminal]
# Start development environment
pnpm docker:dev

# Start in background
pnpm docker:dev:detach

# Start standalone database (alternative to Supabase)
pnpm docker:db

# Stop all containers
pnpm docker:down

# View logs
pnpm docker:logs

# Reset Docker volumes
pnpm docker:reset

# Production build
pnpm docker:prod
```

## Troubleshooting

### Container won't start

Check logs for specific errors:

```bash [Terminal]
docker compose -f docker-compose.dev.yml logs api
```

### Database connection failed

Ensure Supabase is running:

```bash [Terminal]
supabase status
```

If using `host.docker.internal`, ensure Docker Desktop is configured to allow it.

### Hot reload not working

Volume mounts require Docker Desktop file sharing. Check Docker settings and ensure your project directory is shared.

### Port already in use

```bash [Terminal]
# Find process using port
lsof -i :3002

# Kill it
kill -9 <PID>
```
