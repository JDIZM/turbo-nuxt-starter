This page documents all environment variables used by the monorepo.

## Quick Reference

### Required Variables

| Variable | Service | Description |
|----------|---------|-------------|
| `DATABASE_URL` | API | PostgreSQL connection string |
| `SUPABASE_URL` | API | Supabase project URL |
| `SUPABASE_ANON_KEY` | API | Supabase anonymous key |
| `SUPABASE_AUTH_JWT_SECRET` | API | JWT secret for auth verification |

### Optional Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `NODE_ENV` | `development` | Environment mode |
| `LOG_LEVEL` | `info` | Logging verbosity |
| `CORS_ORIGIN` | `http://localhost:3001` | Allowed CORS origins |
| `API_PORT` | `3002` | Express API port |
| `NUXT_PORT` | `3001` | Nuxt frontend port |

## Detailed Configuration

### Database

```env
# PostgreSQL connection string
# Format: postgresql://USER:PASSWORD@HOST:PORT/DATABASE

# Local development (with docker-compose.db.yml)
DATABASE_URL=postgresql://postgres:postgres@localhost:54322/postgres

# Docker development (connects to 'db' service)
DATABASE_URL=postgresql://postgres:postgres@db:5432/postgres

# Production (Supabase or other hosted PostgreSQL)
DATABASE_URL=postgresql://user:password@db.supabase.co:5432/postgres
```

### Supabase

```env
# Supabase project URL
SUPABASE_URL=https://your-project.supabase.co

# Option 1: New key system (2025+)
SUPABASE_PUBLISHABLE_KEY=your-publishable-key
SUPABASE_SECRET_KEY=your-secret-key

# Option 2: Legacy keys (still supported)
SUPABASE_ANON_KEY=your-anon-key
SUPABASE_AUTH_JWT_SECRET=your-jwt-secret
```

Get these values from:
- Local: `supabase status`
- Production: Supabase Dashboard → Settings → API

### API Server

```env
# Server configuration
API_PORT=3002
NODE_ENV=production

# Logging
LOG_LEVEL=info  # trace, debug, info, warn, error, fatal

# CORS (comma-separated origins)
CORS_ORIGIN=https://app.example.com,https://admin.example.com
```

### Nuxt Frontend

```env
# Server configuration
NUXT_PORT=3001
NODE_ENV=production

# API connection
NUXT_PUBLIC_API_BASE=https://api.example.com
```

### PostgreSQL Container

```env
# Used by docker-compose.db.yml
POSTGRES_PORT=54322
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=postgres
```

## Environment Files

### .env.example

Template with all variables and documentation:

```env
# Environment
NODE_ENV=development

# PostgreSQL Configuration
POSTGRES_PORT=54322
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=postgres

# Database Connection String
DATABASE_URL=postgresql://postgres:postgres@localhost:54322/postgres

# Supabase Configuration
SUPABASE_URL=http://localhost:54321
SUPABASE_ANON_KEY=
SUPABASE_AUTH_JWT_SECRET=

# CORS Configuration
CORS_ORIGIN=http://localhost:3000,http://localhost:3001

# Application Ports
NUXT_PORT=3001
API_PORT=3002
NITRO_PORT=3004
DOCS_PORT=3003
STORYBOOK_PORT=6006

# API Base URL
NUXT_PUBLIC_API_BASE=http://localhost:3002

# Logging
LOG_LEVEL=info
```

### Local Development

Copy `.env.example` to `.env` and customize:

```bash [Terminal]
cp .env.example .env
```

### Docker Development

`docker-compose.dev.yml` sets most variables automatically. The database URL connects to the `db` container:

```yaml
environment:
  - DATABASE_URL=postgresql://postgres:postgres@db:5432/postgres
```

### Production (GCP)

Secrets are stored in GCP Secret Manager and injected by Cloud Run:

```hcl
# In Terraform (cloud-run.tf)
env {
  name = "DATABASE_URL"
  value_source {
    secret_key_ref {
      secret  = "database-url"
      version = "latest"
    }
  }
}
```

## Setting Secrets

### GCP Secret Manager (Production)

```bash [Terminal]
# Set a secret
echo -n "your-value" | gcloud secrets versions add SECRET_NAME --data-file=-

# View secret (latest version)
gcloud secrets versions access latest --secret=SECRET_NAME

# List all secrets
gcloud secrets list
```

### GitHub Actions

Add secrets in GitHub repository settings:

1. Settings → Secrets and variables → Actions
2. Click "New repository secret"
3. Add name and value

### Local Supabase

Get credentials after starting Supabase:

```bash [Terminal]
supabase start
supabase status
```

Copy the output values to your `.env` file.

## Security Best Practices

::prose-warning
Never commit secrets to version control!
::

1. **Use `.env.example`** for documentation, not actual values
2. **Add `.env` to `.gitignore`** (already configured)
3. **Use Secret Manager** in production
4. **Rotate secrets regularly**
5. **Use minimal permissions** for service accounts

## Troubleshooting

### Variable not found

Check the variable is set:

```bash [Terminal]
# Local
echo $DATABASE_URL

# Docker
docker exec turbo-api-dev printenv DATABASE_URL

# Cloud Run
gcloud run services describe turbo-api --region europe-west1 --format='yaml(spec.template.spec.containers[0].env)'
```

### Secret access denied

Ensure the service account has `secretmanager.secretAccessor` role:

```bash [Terminal]
gcloud projects get-iam-policy PROJECT_ID \
  --flatten="bindings[].members" \
  --filter="bindings.role:roles/secretmanager.secretAccessor"
```

### Database connection failed

Verify the connection string format:

```
postgresql://USER:PASSWORD@HOST:PORT/DATABASE
```

Special characters in password must be URL-encoded.
