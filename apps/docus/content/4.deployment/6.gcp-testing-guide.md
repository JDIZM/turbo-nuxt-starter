This guide walks through creating a **test GCP project from scratch** to validate the complete deployment process before production use.

::prose-warning
This creates real GCP resources that will incur costs. Remember to destroy resources after testing.
::

## Why Test in a Separate Project?

- Validate infrastructure code without affecting production
- Train team members on deployment process
- Test infrastructure changes safely
- Verify cost estimates
- Practice disaster recovery procedures

## Prerequisites

::steps

### Install Required Tools

```bash [Terminal]
# Install gcloud CLI
# macOS
brew install google-cloud-sdk

# Or download from https://cloud.google.com/sdk/docs/install

# Install Terraform
brew install terraform

# Verify installations
gcloud --version
terraform --version
```

### Authenticate with Google Cloud

```bash [Terminal]
gcloud auth login
gcloud auth application-default login
```

::

## Part 1: Create Test Project

### 1. Create New Project

```bash [Terminal]
# Set variables
export TEST_PROJECT_ID="turbo-test-$(date +%Y%m%d)"
export TEST_PROJECT_NAME="Turbo Nuxt Test"
export BILLING_ACCOUNT_ID="YOUR_BILLING_ACCOUNT_ID"

# Find your billing account ID
gcloud billing accounts list

# Create project
gcloud projects create $TEST_PROJECT_ID \
  --name="$TEST_PROJECT_NAME" \
  --set-as-default

# Link billing account (required for Cloud Run)
gcloud billing projects link $TEST_PROJECT_ID \
  --billing-account=$BILLING_ACCOUNT_ID

# Verify project is active
gcloud projects describe $TEST_PROJECT_ID
```

### 2. Enable Required APIs

```bash [Terminal]
# Enable all necessary APIs at once
gcloud services enable \
  run.googleapis.com \
  artifactregistry.googleapis.com \
  secretmanager.googleapis.com \
  compute.googleapis.com \
  iam.googleapis.com \
  iamcredentials.googleapis.com \
  cloudresourcemanager.googleapis.com \
  --project=$TEST_PROJECT_ID

# Verify APIs are enabled
gcloud services list --enabled --project=$TEST_PROJECT_ID
```

### 3. Set Project Context

```bash [Terminal]
# Set as default project
gcloud config set project $TEST_PROJECT_ID

# Verify current project
gcloud config get-value project
```

## Part 2: Configure Terraform

### 1. Prepare Terraform Variables

```bash [Terminal]
cd infra/terraform

# Copy example configuration
cp terraform.tfvars.example terraform.tfvars
```

### 2. Edit Terraform Variables

Edit `terraform.tfvars`:

```hcl [infra/terraform/terraform.tfvars]
# Project Configuration
project_id = "turbo-test-20251218"  # Use your $TEST_PROJECT_ID
region     = "europe-west1"

# GitHub Configuration (for CI/CD)
github_owner = "your-username"
github_repo  = "turbo-nuxt-starter"

# Optional: Custom Domains (leave commented for testing)
# api_domain  = "api.test.example.com"
# nuxt_domain = "app.test.example.com"
```

### 3. Initialize Terraform

```bash [Terminal]
# Initialize Terraform
terraform init

# Validate configuration
terraform validate

# Check what will be created
terraform plan
```

**Expected Resources:**

- 1 Artifact Registry repository
- 3 Cloud Run services (api, nuxt, docus)
- 4 Secret Manager secrets
- 1 Service account for deployments
- Workload Identity Pool for GitHub Actions
- IAM policy bindings

### 4. Apply Infrastructure

```bash [Terminal]
# Create all resources
terraform apply

# Review the plan and type 'yes' when prompted
```

⏱️ **Expected Time**: 2-3 minutes

### 5. Save Terraform Outputs

```bash [Terminal]
# Save important outputs
terraform output -json > outputs.json

# View specific outputs
terraform output api_service_url
terraform output nuxt_service_url
terraform output docus_service_url
terraform output github_actions_service_account
terraform output workload_identity_provider
```

## Part 3: Configure Secrets

### 1. Set Database URL

```bash [Terminal]
# Using Supabase (recommended for testing)
echo -n "postgresql://postgres:password@db.example.supabase.co:5432/postgres" | \
  gcloud secrets versions add database-url --data-file=-

# Or using Cloud SQL (more expensive)
# See: https://cloud.google.com/sql/docs/postgres/quickstart
```

### 2. Set Supabase Credentials

```bash [Terminal]
# Supabase URL
echo -n "https://your-project.supabase.co" | \
  gcloud secrets versions add supabase-url --data-file=-

# Supabase Anonymous Key
echo -n "your-anon-key-here" | \
  gcloud secrets versions add supabase-anon-key --data-file=-

# Supabase JWT Secret
echo -n "your-jwt-secret-here" | \
  gcloud secrets versions add supabase-jwt-secret --data-file=-
```

::prose-info
Get your Supabase credentials from: [app.supabase.com](https://app.supabase.com) → Project Settings → API
::

### 3. Verify Secrets

```bash [Terminal]
# List all secrets
gcloud secrets list

# Check secret versions (doesn't show values)
gcloud secrets versions list database-url
gcloud secrets versions list supabase-url
gcloud secrets versions list supabase-anon-key
gcloud secrets versions list supabase-jwt-secret
```

## Part 4: Build and Push Initial Images

### 1. Configure Docker Authentication

```bash [Terminal]
# Configure Docker to use gcloud for authentication
gcloud auth configure-docker europe-west1-docker.pkg.dev

# Verify authentication
gcloud auth print-access-token | docker login -u oauth2accesstoken \
  --password-stdin https://europe-west1-docker.pkg.dev
```

### 2. Build and Push API

```bash [Terminal]
# From repository root
cd ../..

# Build API image
docker build \
  -f apps/api/Dockerfile \
  -t europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/api:latest \
  .

# Push to Artifact Registry
docker push europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/api:latest
```

⏱️ **Expected Time**: 5-10 minutes (first build)

### 3. Build and Push Nuxt

```bash [Terminal]
# Build Nuxt image
docker build \
  -f apps/nuxt/Dockerfile \
  -t europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/nuxt:latest \
  .

# Push to Artifact Registry
docker push europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/nuxt:latest
```

⏱️ **Expected Time**: 5-10 minutes

### 4. Build and Push Docus

```bash [Terminal]
# Build Docus image
docker build \
  -f apps/docus/Dockerfile \
  -t europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/docus:latest \
  .

# Push to Artifact Registry
docker push europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/docus:latest
```

⏱️ **Expected Time**: 3-5 minutes

### 5. Verify Images

```bash [Terminal]
# List images in Artifact Registry
gcloud artifacts docker images list \
  europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo

# Expected output:
# - turbo-repo/api:latest
# - turbo-repo/nuxt:latest
# - turbo-repo/docus:latest
```

## Part 5: Verify Deployment

### 1. Check Cloud Run Services

```bash [Terminal]
# List all Cloud Run services
gcloud run services list --region=europe-west1

# Get service URLs
API_URL=$(gcloud run services describe turbo-api --region=europe-west1 --format="value(status.url)")
NUXT_URL=$(gcloud run services describe turbo-nuxt --region=europe-west1 --format="value(status.url)")
DOCUS_URL=$(gcloud run services describe turbo-docus --region=europe-west1 --format="value(status.url)")

echo "API:   $API_URL"
echo "Nuxt:  $NUXT_URL"
echo "Docus: $DOCUS_URL"
```

### 2. Test API Health Endpoint

```bash [Terminal]
# Test API health check
curl $API_URL/health

# Expected response:
# {"status":"ok","timestamp":"2025-12-18T10:30:00.000Z","uptime":123.456}
```

### 3. Test API Documentation

```bash [Terminal]
# Open API docs in browser
open "$API_URL/docs"

# Or check if Swagger UI is accessible
curl -I "$API_URL/docs"
```

### 4. Test Nuxt App

```bash [Terminal]
# Open Nuxt app in browser
open "$NUXT_URL"

# Or check if app responds
curl -I "$NUXT_URL"
```

### 5. Test Docus Documentation

```bash [Terminal]
# Open Docus site in browser
open "$DOCUS_URL"

# Or check response
curl -I "$DOCUS_URL"
```

### 6. Check Service Logs

```bash [Terminal]
# View API logs
gcloud run services logs read turbo-api \
  --region=europe-west1 \
  --limit=50

# View Nuxt logs
gcloud run services logs read turbo-nuxt \
```

### 7. Test API Endpoints

```bash [Terminal]
cd infra/terraform

# Get the provider path
terraform output workload_identity_provider
```

### 2. Configure GitHub Secrets

Add these secrets to your GitHub repository:

1. Go to: `https://github.com/your-username/turbo-nuxt-starter/settings/secrets/actions`

2. Add secrets:
   - `GCP_PROJECT_ID`: Your test project ID

## Part 7: Monitor Costs

### 1. View Current Costs

```bash [Terminal]
# View billing for the test project
gcloud billing accounts describe $BILLING_ACCOUNT_ID

# Check project costs (may take 24 hours to appear)
gcloud beta billing accounts --billing-account=$BILLING_ACCOUNT_ID \
  budgets list
```

### 2. Set Budget Alert (Optional)

```bash [Terminal]
# Create budget alert at $10
gcloud billing budgets create \
  --billing-account=$BILLING_ACCOUNT_ID \
  --display-name="Test Project Budget" \
  --budget-amount=10 \
  --threshold-rule=percent=50 \
  --threshold-rule=percent=90 \
  --threshold-rule=percent=100
```

### 3. Expected Costs (Idle)

| Resource | Daily Cost | Monthly Cost |
| ---------- | ----------- | ------------- |
| **Cloud Run (min=0)** | ~$0.00 | ~$0.00 |
| **Cloud Run (min=1)** | ~$0.40 | ~$12.00 |
| **Artifact Registry** | ~$0.03 | ~$1.00 |
| **Secret Manager** | ~$0.00 | ~$0.00 |
| **Total (scale to zero)** | ~$0.03 | ~$1.00 |
| **Total (always-on)** | ~$0.43 | ~$13.00 |

::prose-info
With `min_instances=0`, services scale to zero when idle, resulting in minimal costs during testing.
::

## Part 8: Cleanup & Teardown

### 1. Destroy Terraform Resources

```bash [Terminal]
cd infra/terraform

# Destroy all infrastructure
terraform destroy

# Type 'yes' when prompted
```

::prose-warning
This will delete all Cloud Run services, secrets, and container images. Ensure you've backed up anything important.
::

### 2. Delete Container Images (Optional)

If terraform destroy doesn't clean up images:

```bash [Terminal]
# Delete all images in Artifact Registry
gcloud artifacts docker images delete \
  europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/api:latest \
  --quiet

gcloud artifacts docker images delete \
  europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/nuxt:latest \
  --quiet

gcloud artifacts docker images delete \
  europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/docus:latest \
  --quiet
```

### 3. Delete Test Project

```bash [Terminal]
# Delete the entire test project
gcloud projects delete $TEST_PROJECT_ID

# Confirm deletion by typing the project ID
```

::prose-warning
Project deletion is permanent after 30 days. During the 30-day period, you can restore it:

```bash
gcloud projects undelete $TEST_PROJECT_ID
```

::

### 4. Verify Deletion

```bash [Terminal]
# List projects (test project should be marked for deletion)
gcloud projects list --filter="projectId:turbo-test-*"

# Unset project from gcloud config
gcloud config unset project
```

## Part 9: Troubleshooting

### API Fails to Start

**Check logs:**

```bash
gcloud run services logs read turbo-api --region=europe-west1 --limit=100
```

**Common issues:**

- Missing secrets (database-url, supabase-url)
- Invalid secret values
- Port not set to 3002
- Health check timeout

**Fix:**

```bash
# Update secrets
echo -n "correct-value" | gcloud secrets versions add database-url --data-file=-

# Redeploy
gcloud run deploy turbo-api \
  --image europe-west1-docker.pkg.dev/$TEST_PROJECT_ID/turbo-repo/api:latest \
  --region europe-west1
```

### Terraform Apply Fails

#### **Error: Workload Identity Pool already exists**

Delete and recreate:

```bash
gcloud iam workload-identity-pools delete github-actions-pool \
  --location=global \
  --quiet

terraform apply
```

#### **Error: API not enabled**

```bash
gcloud services enable <api-name>.googleapis.com
terraform apply
```

### Docker Push Permission Denied

```bash
# Reauthenticate
gcloud auth configure-docker europe-west1-docker.pkg.dev

# Check permissions
gcloud projects get-iam-policy $TEST_PROJECT_ID
```

### Budget Exceeded During Testing

```bash
# Immediately shut down services
terraform destroy

# Or scale to zero
gcloud run services update turbo-api \
  --min-instances=0 \
  --region=europe-west1
```

## Testing Checklist

Use this checklist to validate the complete deployment:

- [ ] GCP project created and billing linked
- [ ] All APIs enabled
- [ ] Terraform apply successful
- [ ] Secrets configured
- [ ] Docker images built and pushed
- [ ] All 3 Cloud Run services running
- [ ] API health check returns 200 OK
- [ ] API docs accessible at /docs
- [ ] Nuxt app loads in browser
- [ ] Docus documentation accessible
- [ ] Service logs show no errors
- [ ] GitHub Actions secrets configured
- [ ] Manual deployment workflow succeeds
- [ ] Budget alert configured (optional)
- [ ] Costs within expected range
- [ ] Terraform destroy completes successfully
- [ ] Test project deleted

## Next Steps

After successful testing:

1. **Create Production Project**: Repeat process with production project ID
2. **Configure Custom Domains**: Add DNS records and update Terraform
3. **Set min_instances**: Consider `min_instances=1` for production
4. **Enable Monitoring**: Set up Cloud Monitoring alerts
5. **Document Findings**: Update team wiki with any lessons learned
