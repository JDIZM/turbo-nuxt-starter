This guide walks through deploying the monorepo to GCP Cloud Run using Terraform.

## Prerequisites

::steps

### Install required tools

```bash [Terminal]
# Install gcloud CLI
# macOS
brew install google-cloud-sdk

# Or download from https://cloud.google.com/sdk/docs/install

# Install Terraform >= 1.5.0
brew install terraform
```

### Authenticate with GCP

**See the complete [Authentication Setup Guide](/deployment/authentication-setup) for detailed instructions.**

Quick setup:

```bash [Terminal]
# CRITICAL: Unset service account credentials if set
unset GOOGLE_APPLICATION_CREDENTIALS

# Authenticate with your Google account
gcloud auth login
gcloud auth application-default login

# Set your project
gcloud config set project YOUR_PROJECT_ID
```

::prose-warning
If `GOOGLE_APPLICATION_CREDENTIALS` is set, it will override gcloud CLI auth and may cause permission errors. Always unset it before running Terraform locally.
::

::

## Terraform Setup

### 1. Configure Variables

```bash [Terminal]
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars`:

```hcl
project_id = "your-gcp-project-id"
region     = "europe-west1"

# Optional: Custom domains
# api_domain  = "api.example.com"
# nuxt_domain = "app.example.com"

# Optional: Secrets (or set via GCP Console)
# database_url        = "postgresql://..."
# supabase_url        = "https://..."
# supabase_anon_key   = "..."
# supabase_jwt_secret = "..."
```

### 2. Create State Bucket (First Time Only)

Terraform uses a GCS bucket to store its state. Create it once:

```bash [Terminal]
# Set your project and region
export PROJECT_ID="your-gcp-project-id"
export REGION="europe-west1"  # Match your terraform.tfvars region

# Create the state bucket
gcloud storage buckets create gs://${PROJECT_ID}-turbo-tfstate \
  --project=${PROJECT_ID} \
  --location=${REGION} \
  --uniform-bucket-level-access
```

Then update `infra/terraform/versions.tf` to use the bucket:

```hcl
backend "gcs" {
  bucket = "your-gcp-project-id-turbo-tfstate"
  prefix = "turbo-nuxt-starter"
}
```

::prose-info
The state bucket stores Terraform's state file, which tracks what resources exist. Without it, Terraform can't manage your infrastructure.
::

### 3. Initialize Terraform

```bash [Terminal]
terraform init
```

### 4. Preview Changes

```bash [Terminal]
terraform plan
```

This shows what resources will be created:

- Artifact Registry repository
- 3 Cloud Run services (api, nuxt, docus)
- Secret Manager secrets
- IAM roles and service accounts
- Workload Identity Pool for GitHub Actions

### 5. Build and Push Docker Images (CRITICAL - Before Apply!)

::prose-warning
**You must push Docker images BEFORE running `terraform apply`**. Cloud Run services require the images to exist or deployment will fail.
::

```bash [Terminal]
# From repository root (go back from infra/terraform)
cd ../..

# Configure Docker authentication (use YOUR region from terraform.tfvars)
gcloud auth configure-docker ${REGION}-docker.pkg.dev

# Example for europe-west2:
gcloud auth configure-docker europe-west2-docker.pkg.dev

# Build and push API (~10 minutes first build)
docker build -f apps/api/Dockerfile \
  -t ${REGION}-docker.pkg.dev/${PROJECT_ID}/turbo-repo/api:latest .
docker push ${REGION}-docker.pkg.dev/${PROJECT_ID}/turbo-repo/api:latest

# Build and push Nuxt (~10 minutes)
docker build -f apps/nuxt/Dockerfile \
  -t ${REGION}-docker.pkg.dev/${PROJECT_ID}/turbo-repo/nuxt:latest .
docker push ${REGION}-docker.pkg.dev/${PROJECT_ID}/turbo-repo/nuxt:latest

# Build and push Docus (~5 minutes)
docker build -f apps/docus/Dockerfile \
  -t ${REGION}-docker.pkg.dev/${PROJECT_ID}/turbo-repo/docus:latest .
docker push ${REGION}-docker.pkg.dev/${PROJECT_ID}/turbo-repo/docus:latest
```

::prose-info
**Total build time**: ~25-30 minutes for all three images on first build. Subsequent builds are faster thanks to Docker layer caching.
::

### 6. Apply Infrastructure

Now that images exist, deploy the Cloud Run services:

```bash [Terminal]
# Go back to terraform directory
cd infra/terraform

# Apply infrastructure
terraform apply
```

Type `yes` when prompted.

## What Gets Created

### Artifact Registry

Container image repository at:
```
europe-west1-docker.pkg.dev/PROJECT_ID/turbo-repo/
```

### Cloud Run Services

| Service | URL | Port |
|---------|-----|------|
| turbo-api | https://turbo-api-xxxxx.run.app | 3002 |
| turbo-nuxt | https://turbo-nuxt-xxxxx.run.app | 3001 |
| turbo-docus | https://turbo-docus-xxxxx.run.app | 80 |

### Secret Manager

Secrets for sensitive configuration:
- `database-url`
- `supabase-url`
- `supabase-anon-key`
- `supabase-jwt-secret`

### GitHub Actions Integration

Workload Identity Federation allows GitHub Actions to authenticate without service account keys:

```
projects/PROJECT_NUM/locations/global/workloadIdentityPools/github-actions-pool/providers/github-provider
```

## Verify Deployment

After `terraform apply` completes, verify all services are running:

```bash [Terminal]
# Get service URLs from Terraform outputs
terraform output api_service_url
terraform output nuxt_service_url
terraform output docus_service_url

# Test API health endpoint
curl $(terraform output -raw api_service_url)/health

# Open services in browser
open $(terraform output -raw api_service_url)/docs  # Swagger docs
open $(terraform output -raw nuxt_service_url)
open $(terraform output -raw docus_service_url)

# Check service logs
gcloud run services logs read turbo-api --region=${REGION} --limit=50
```

## Configure Secrets

Set secrets via GCP Console or gcloud:

```bash [Terminal]
# Set database URL
echo -n "postgresql://user:pass@host:5432/db" | \
  gcloud secrets versions add database-url --data-file=-

# Set Supabase URL
echo -n "https://your-project.supabase.co" | \
  gcloud secrets versions add supabase-url --data-file=-

# Set Supabase anon key
echo -n "your-anon-key" | \
  gcloud secrets versions add supabase-anon-key --data-file=-

# Set JWT secret
echo -n "your-jwt-secret" | \
  gcloud secrets versions add supabase-jwt-secret --data-file=-
```

## Custom Domains

To use custom domains:

### 1. Update Terraform variables

```hcl
api_domain  = "api.example.com"
nuxt_domain = "app.example.com"
```

### 2. Apply changes

```bash [Terminal]
terraform apply
```

### 3. Configure DNS

Add CNAME records pointing to the Cloud Run URLs:

```
api.example.com  CNAME  turbo-api-xxxxx.run.app
app.example.com  CNAME  turbo-nuxt-xxxxx.run.app
```

Cloud Run automatically provisions SSL certificates.

## Scaling Configuration

Default configuration optimizes for cost:

```hcl
min_instances = 0   # Scale to zero when idle
max_instances = 10  # Handle traffic spikes
```

For production with SLA requirements:

```hcl
min_instances = 1   # Always-on for lower latency
max_instances = 20  # Handle more traffic
```

## Updating Services

After the initial setup, GitHub Actions handles deployments automatically. See [CI/CD Guide](/deployment/ci-cd).

For manual updates:

```bash [Terminal]
# Rebuild and push
docker build -f apps/api/Dockerfile \
  -t europe-west1-docker.pkg.dev/PROJECT_ID/turbo-repo/api:v2 .
docker push europe-west1-docker.pkg.dev/PROJECT_ID/turbo-repo/api:v2

# Deploy new revision
gcloud run deploy turbo-api \
  --image europe-west1-docker.pkg.dev/PROJECT_ID/turbo-repo/api:v2 \
  --region europe-west1
```

## Destroying Infrastructure

To remove all resources:

```bash [Terminal]
terraform destroy
```

::prose-warning
This permanently deletes all Cloud Run services, secrets, and container images.
::

## Troubleshooting

### Permission denied

Ensure your GCP account has the required roles:
- `roles/owner` or
- `roles/editor` + `roles/iam.securityAdmin`

### Service account issues

```bash [Terminal]
# Check service accounts
gcloud iam service-accounts list

# Check IAM bindings
gcloud projects get-iam-policy PROJECT_ID
```

### Cloud Run deployment fails

Check container logs:

```bash [Terminal]
gcloud run services logs read turbo-api --region europe-west1
```
