The project includes GitHub Actions workflows for CI/CD.

## Workflows

### ci.yml - Continuous Integration

Runs on all pull requests and pushes to main:

- **Lint & Typecheck** - ESLint, Prettier, TypeScript
- **Test** - Unit tests with Vitest (Node 20 & 22)
- **Build** - Verify all packages build successfully

```yaml
name: CI

on:
  pull_request:
  push:
    branches: [main]

jobs:
  lint-and-typecheck:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile --ignore-scripts
      - run: pnpm lint:check
      - run: pnpm format:check
      - run: pnpm typecheck

  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: ['20', '22']
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile --ignore-scripts
      - run: pnpm test:unit

  build:
    runs-on: ubuntu-latest
    needs: [lint-and-typecheck]
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile --ignore-scripts
      - run: pnpm build
```

### deploy.yml - Deployment

Runs on pushes to main or manual trigger:

- Detects which services changed
- Builds Docker images
- Pushes to Artifact Registry
- Deploys to Cloud Run

Key features:
- **Path filtering** - Only deploys changed services
- **Workload Identity** - Keyless authentication
- **Manual trigger** - Deploy specific services on demand

## Setting Up GitHub Actions

### 1. Configure Repository Secrets

After running `terraform apply`, add these secrets to your GitHub repository:

| Secret | Value Example | How to Get | Why Needed |
|--------|---------------|------------|------------|
| `GCP_PROJECT_ID` | `my-project-123` | Your GCP project ID from console | Identifies which GCP project to deploy to |
| `GCP_REGION` | `europe-west2` | Your chosen region (match terraform.tfvars) | Specifies where Cloud Run services run |
| `GCP_WORKLOAD_IDENTITY_PROVIDER` | `projects/123.../providers/github-provider` | `terraform output workload_identity_provider` | Used by Google's auth action for OIDC |
| `GCP_SERVICE_ACCOUNT` | `github-actions-deploy@PROJECT.iam.gserviceaccount.com` | `terraform output github_actions_service_account` | Service account to impersonate |

::prose-info
**Get Terraform outputs**: Run `terraform output -json` in `infra/terraform/` to see all values. The Workload Identity Provider and Service Account are created during `terraform apply`.
::

### 2. Add Secrets in GitHub

1. Go to your repository → Settings → Secrets and variables → Actions
2. Click "New repository secret"
3. Add each secret with its value

### 3. Verify Workload Identity

The Terraform configuration sets up Workload Identity Federation, which allows GitHub Actions to authenticate without storing service account keys.

Verify the setup:

```bash [Terminal]
# Check the service account
gcloud iam service-accounts describe \
  github-actions-deploy@YOUR_GCP_PROJECT_ID.iam.gserviceaccount.com

# Check Workload Identity Pool
gcloud iam workload-identity-pools describe github-actions-pool \
  --location global \
  --project YOUR_GCP_PROJECT_ID

# Verify service account has correct roles
gcloud projects get-iam-policy YOUR_GCP_PROJECT_ID \
  --flatten="bindings[].members" \
  --filter="bindings.members:github-actions-deploy"
```

## Workflow Triggers

### Automatic Deployment

Pushes to `main` automatically deploy changed services:

```yaml
on:
  push:
    branches: [main]
```

### Manual Deployment

Use the workflow_dispatch trigger to deploy specific services:

1. Go to Actions → Deploy to Cloud Run
2. Click "Run workflow"
3. Select services to deploy: `api`, `nuxt`, `docus`, or `all`

### Path Filtering

The workflow detects which services changed:

```yaml
- uses: dorny/paths-filter@v3
  with:
    filters: |
      api:
        - 'apps/api/**'
        - 'packages/helpers/**'
        - 'packages/logger/**'
      nuxt:
        - 'apps/nuxt/**'
        - 'packages/ui/**'
```

## Security

### Limited Permissions

The GitHub Actions service account has minimal permissions:

| Role | Purpose |
|------|---------|
| `roles/run.developer` | Deploy to Cloud Run |
| `roles/artifactregistry.writer` | Push container images |
| `roles/secretmanager.secretAccessor` | Read secrets |

It cannot:
- Create or delete Cloud Run services
- Modify IAM policies
- Access other GCP resources

### Workload Identity

No service account keys are stored in GitHub. Authentication uses OIDC:

```yaml
permissions:
  contents: read
  id-token: write  # Required for Workload Identity

steps:
  - uses: google-github-actions/auth@v2
    with:
      workload_identity_provider: ${{ secrets.GCP_WORKLOAD_IDENTITY_PROVIDER }}
      service_account: ${{ secrets.GCP_SERVICE_ACCOUNT }}
```

## Docker Build Caching

The workflow uses GitHub Actions cache for faster builds:

```yaml
- uses: docker/build-push-action@v6
  with:
    cache-from: type=gha
    cache-to: type=gha,mode=max
```

## Monitoring Deployments

### GitHub Actions UI

View workflow runs:
- Repository → Actions → Deploy to Cloud Run

### GCP Console

View Cloud Run revisions:
- GCP Console → Cloud Run → Select service → Revisions

### CLI

```bash [Terminal]
# List recent revisions
gcloud run revisions list --service turbo-api --region YOUR_GCP_REGION

# View logs
gcloud run services logs read turbo-api --region YOUR_GCP_REGION
```

## Troubleshooting

### Workflow fails on authentication

1. Verify secrets are set correctly in GitHub
2. Check Workload Identity Pool is configured
3. Ensure service account has required roles

```bash [Terminal]
# Verify service account exists
gcloud iam service-accounts describe \
  github-actions-deploy@YOUR_GCP_PROJECT_ID.iam.gserviceaccount.com

# Check Workload Identity binding
gcloud iam service-accounts get-iam-policy \
  github-actions-deploy@YOUR_GCP_PROJECT_ID.iam.gserviceaccount.com
```

### Docker build fails

Check container logs in the Actions run. Common issues:

- Missing dependencies in Dockerfile
- Build context too large
- pnpm lockfile out of sync

### Deployment succeeds but service fails

Check Cloud Run logs:

```bash [Terminal]
gcloud run services logs read turbo-api --region YOUR_GCP_REGION --limit 100
```

Common issues:
- Missing environment variables
- Secret access denied
- Health check failures
