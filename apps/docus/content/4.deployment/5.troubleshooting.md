This guide covers common issues and their solutions.

## Local Development

### Port already in use

```bash [Terminal]
Error: listen EADDRINUSE: address already in use :::3002
```

**Solution:**

```bash [Terminal]
# Find process using the port
lsof -i :3002

# Kill the process
kill -9 <PID>

# Or use a different port
API_PORT=3010 pnpm dev:api
```

### pnpm install fails

```bash [Terminal]
ERR_PNPM_LOCKFILE_MISSING  Lockfile is not up to date
```

**Solution:**

```bash [Terminal]
# Remove node_modules and reinstall
rm -rf node_modules
rm -rf **/node_modules
pnpm install

# If still failing, update lockfile
pnpm install --no-frozen-lockfile
```

### TypeScript errors after install

```bash [Terminal]
Cannot find module 'helpers' or its corresponding type declarations
```

**Solution:**

```bash [Terminal]
# Build packages first
pnpm build

# Or run prepare scripts
pnpm turbo prepare
```

### Database connection refused

```bash [Terminal]
Error: connect ECONNREFUSED 127.0.0.1:54322
```

**Solution:**

```bash [Terminal]
# Check if database is running
docker ps | grep postgres

# Start the database
pnpm docker:db

# Wait for health check
docker exec turbo-postgres-local pg_isready -U postgres
```

## Docker Issues

### Container fails to start

**Check logs:**

```bash [Terminal]
docker compose -f docker-compose.dev.yml logs api
```

**Common causes:**

1. **Missing environment variables** - Check `.env` file exists
2. **Port conflicts** - Another service using the same port
3. **Build failures** - Check Dockerfile syntax

### Volume mount issues

```bash [Terminal]
Error: ENOENT: no such file or directory
```

**Solution (macOS):**

1. Open Docker Desktop
2. Go to Settings → Resources → File Sharing
3. Add your project directory

### Out of disk space

```bash [Terminal]
no space left on device
```

**Solution:**

```bash [Terminal]
# Remove unused Docker data
docker system prune -a

# Remove specific volumes
docker volume prune

# Check disk usage
docker system df
```

### Hot reload not working

**Solution:**

1. Ensure volume mounts are correct in `docker-compose.dev.yml`
2. Check file permissions
3. Restart containers:

```bash [Terminal]
pnpm docker:down
pnpm docker:dev
```

## GCP Cloud Run

### Deployment fails - Permission denied

```bash [Terminal]
ERROR: (gcloud.run.deploy) PERMISSION_DENIED
```

**Solution:**

```bash [Terminal]
# Check your roles
gcloud projects get-iam-policy YOUR_GCP_PROJECT_ID \
  --flatten="bindings[].members" \
  --filter="bindings.members:YOUR_EMAIL"

# Grant Cloud Run admin role
gcloud projects add-iam-policy-binding YOUR_GCP_PROJECT_ID \
  --member="user:YOUR_EMAIL" \
  --role="roles/run.admin"
```

### Service fails to start - Health check timeout

```bash [Terminal]
Revision 'turbo-api-xxxxx' is not ready and cannot serve traffic.
The user-provided container failed to start and listen on the port defined by the PORT environment variable.
```

**Common causes:**

1. **Wrong port** - Ensure the app listens on the correct port:

```typescript
// apps/api/src/server.ts
const PORT = process.env.API_PORT || process.env.PORT || 3002;
app.listen(PORT, '0.0.0.0', () => {
  console.log(`Server running on port ${PORT}`);
});
```

2. **Missing dependencies** - Check Dockerfile copies all required files

3. **Startup crash** - Check logs:

```bash [Terminal]
gcloud run services logs read turbo-api --region europe-west1 --limit 100
```

### Secret access denied

```bash [Terminal]
Permission 'secretmanager.versions.access' denied for resource
```

**Solution:**

```bash [Terminal]
# Grant secret access to service account
gcloud secrets add-iam-policy-binding DATABASE_URL \
  --member="serviceAccount:turbo-api-service@PROJECT.iam.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"
```

### Container too slow to start

```bash [Terminal]
Container called exit(1)
```

**Solution:**

Increase startup timeout in `cloud-run.tf`:

```hcl
startup_probe {
  http_get {
    path = "/health"
    port = 3002
  }
  initial_delay_seconds = 30  # Increase from 10
  period_seconds        = 10
  failure_threshold     = 5   # Increase from 3
}
```

## GitHub Actions

### Workload Identity authentication fails

```bash [Terminal]
Error: google-github-actions/auth failed with:
error fetching token: Error: identity pool does not exist
```

**Solution:**

1. Verify Terraform created the Workload Identity Pool:

```bash [Terminal]
gcloud iam workload-identity-pools list --location global
```

2. Check GitHub secrets match Terraform outputs:

```bash [Terminal]
cd infra/terraform
terraform output workload_identity_provider
terraform output github_actions_service_account
```

3. Verify repository attribute matches:

The Workload Identity Pool provider is configured for `JDIZM/turbo-nuxt-starter`. Update `infra/terraform/main.tf` if your repository is different.

### Docker push fails

```bash [Terminal]
denied: Permission "artifactregistry.repositories.uploadArtifacts" denied
```

**Solution:**

```bash [Terminal]
# Grant Artifact Registry writer role
gcloud projects add-iam-policy-binding YOUR_GCP_PROJECT_ID \
  --member="serviceAccount:github-actions-deploy@YOUR_GCP_PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/artifactregistry.writer"
```

### Build cache not working

Ensure cache action is before build:

```yaml
- uses: docker/setup-buildx-action@v3
- uses: docker/build-push-action@v6
  with:
    cache-from: type=gha
    cache-to: type=gha,mode=max
```

## Terraform

### State lock error

```bash [Terminal]
Error: Error locking state: Error acquiring the state lock
```

**Solution:**

```bash [Terminal]
# Force unlock (use with caution)
terraform force-unlock LOCK_ID
```

### Provider version conflict

```bash [Terminal]
Error: Failed to query available provider packages
```

**Solution:**

```bash [Terminal]
# Remove lock file and reinitialize
rm .terraform.lock.hcl
terraform init -upgrade
```

### Resource already exists

```bash [Terminal]
Error: Error creating Service: googleapi: Error 409: Resource already exists
```

**Solution:**

Import the existing resource:

```bash [Terminal]
terraform import google_cloud_run_v2_service.api projects/PROJECT/locations/REGION/services/turbo-api
```

## Database

### Migration fails

```bash [Terminal]
Error: relation "users" already exists
```

**Solution:**

```bash [Terminal]
# Check current migration state
pnpm --filter=db-schema run db:studio

# Force push (development only!)
pnpm --filter=db-schema run db:push --force
```

### Connection pool exhausted

```bash [Terminal]
Error: too many connections for role "postgres"
```

**Solution:**

Configure connection pooling in Supabase or use PgBouncer.
